Security & Privacy

What stays local, what this dashboard can and can’t do

{{ icon_lock('icon') }}Where things live

  • Your IMAP credentials stay only in a local config.json file. The dashboard never opens, parses, serves, or logs that file — it only ever passes its file path as an argument to Mback.py.
  • Full email content and attachments stay only in your local backups/ folder as individual .eml files. Nothing is uploaded anywhere.
  • The dashboard binds only to 127.0.0.1 and is not reachable from your network or the internet.
  • Flask’s debug mode is always disabled, so the interactive debugger/console is never exposed.
  • No external analytics, CDNs, remote fonts, trackers, or third-party APIs are loaded by any page.
  • All IMAP actions performed by Mback.py are read-only — it never deletes, moves, marks, or sends mail.
  • .gitignore is set up to keep config.json, logs, .eml files, backups/, and the SQLite database out of version control.
  • The public/portfolio demo mode uses only fictional data (see Demo Notice) and never connects to a real mailbox.

Binding to localhost protects this app from your network and the internet — it does not protect it from another process or person already logged into your Windows account. If your Windows account itself is compromised, this app offers no additional protection beyond that account’s own security.

{{ icon_check('icon') }}Recommended practices

  • Use an app password (not your main account password) for IMAP access where your provider supports it.
  • Enable full-disk or folder-level encryption on the machine that stores your backups.
  • Keep your Windows account itself protected with a strong password and screen lock.
  • Periodically test restoring from a .eml file to confirm your backups are actually usable.
  • Keep Python and this project’s dependencies up to date.
  • Never forward this dashboard’s port through your router — it is designed to stay on localhost only.
