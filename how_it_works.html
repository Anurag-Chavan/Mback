Full initial backup

On the first run for a folder, Mback follows the configured initial_backup_mode. With "all", it saves every message currently available in that folder. With "recent", it saves messages within the configured days_to_backup window. Each message is stored as an individual .eml file, and its outcome is recorded in a local SQLite database.

Incremental, UID-based backup

Every IMAP message has a UID, a unique identifier within its folder. After the first run, Mback asks the server only for UIDs higher than the highest UID already recorded by the backup engine. Later runs are fast and do not normally re-download mail that has already been backed up.

UIDVALIDITY awareness

UIDs are only guaranteed stable while a folder’s UIDVALIDITY value remains unchanged. Mback checks this value on every run. If the server ever reassigns UIDs, Mback detects the change, performs a safe re-sync, and never overwrites a local file it already saved.

Per-message retry ledger

Every individual message has its own SQLite row recording whether it was backed up or failed, together with an attempt count and the latest error. A message that fails once is retried automatically on a later run, even if later messages in the same folder already succeeded. A temporary failure is therefore not silently skipped.

Local SQLite state

Per-folder cursors and per-message status live in the local backup_state.db SQLite file beside your backups. The database allows the backup engine to resume consistently after an interruption and supports the dashboard’s read-only status views.

Read-only, by design

Mback opens folders in read-only mode and issues search and fetch commands only. It does not mark messages as read, delete messages, move mail, or modify mailbox content. See Security & Privacy for the full local-data model and recommended practices.

The dashboard is separate from the backup engine

This dashboard does not connect directly to your mail server. It reads local backup metadata from backup_state.db and, when you explicitly use the button, starts the existing Mback.py script through one fixed local command. The dashboard has no separate IMAP credentials or mailbox logic of its own.

Manual runs, with automation as an option

You can use the dashboard’s Run Backup Now button whenever you want to trigger a manual backup. You can also run Mback.py independently through Windows Task Scheduler or another scheduler for automatic daily backups; the dashboard does not need to be open for scheduled runs.

Mback is designed to reduce exposure by keeping mail data local by default and using read-only access. It is not a substitute for your own backup, endpoint-security, encryption, or compliance practices, and it makes no legal or compliance guarantees.
