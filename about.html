About This Project

A local-first email backup tool with a small operational dashboard

The problem

Small businesses and individuals running their own domain mail often have no simple, self-hosted way to keep an independent copy of their mailbox — most options are either a paid cloud service or a manual, error-prone export. Mback is a small, local-first tool that solves this with a script and a lightweight control panel, keeping the data on the user’s own machine.

Objective

Provide reliable, incremental, read-only IMAP backups with clear visibility into what succeeded and what needs attention — without requiring a server, an account, or any data leaving the user’s computer.

Tech stack

  • Python
  • imaplib
  • sqlite3
  • Flask
  • HTML
  • CSS
  • JavaScript
  • Windows Task Scheduler (optional)

Engineering concepts demonstrated

  • Incremental ingestion — UID-based cursors avoid re-fetching data that’s already been captured.
  • Persistence — per-folder and per-message state tracked in SQLite, safe to interrupt and resume.
  • Failure handling & retries — a dedicated retry ledger ensures a single failed message is never silently dropped.
  • Data safety — strictly read-only mailbox access, parameterized queries, and path validation before serving any file.
  • Local-first architecture — no server, no account, no data leaving the machine by default.
  • User interface design — a small multi-page dashboard that turns raw database state into something scannable at a glance.

Project highlights

  • Full initial backup plus true incremental UID-based backup on every later run.
  • UIDVALIDITY-aware resync that never overwrites an existing local file.
  • A per-message retry ledger so a single failure can’t be masked by later successes.
  • A dashboard that runs the backup engine as a fixed local command — never accepting a path or command from the browser.
  • A demo mode that swaps in fully fictional data for safe screenshots, with real actions disabled.
