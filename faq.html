Frequently Asked Questions

Common questions about how Mback and this dashboard behave

Does Mback delete or modify mailbox emails?

No. Mback opens configured folders in read-only mode and uses search and fetch operations only. It does not delete, move, mark as read, or otherwise modify messages on the mail server.

What does the first backup do?

On the first run for a folder, Mback follows the configured initial_backup_mode. In "all" mode it backs up every message currently in the folder. In "recent" mode it backs up only the configured recent time window. Each backup result is stored in SQLite so later runs can continue incrementally.

How are later runs incremental?

Mback remembers the highest UID it has processed for each folder. On later runs, it asks the server for messages with higher UIDs, so successfully backed-up messages are not normally downloaded again.

What is UIDVALIDITY?

UIDVALIDITY is an IMAP value that tells clients whether a folder’s UID sequence is still valid. If it changes, old UIDs may no longer refer to the same messages. Mback detects this condition and safely re-syncs instead of trusting an outdated cursor.

What happens if a message download fails?

Mback stores a failed status, an attempt count, and a limited error record in its local retry ledger. On the next run, failed messages are retried before newly discovered mail is processed.

Does it save attachments?

Yes. Each message is saved as a complete .eml file, which preserves the original message structure and included attachments.

Where are backups stored?

Backups are stored locally in the backups/ folder beside Mback.py, organized by the configured mail folder. Nothing is uploaded by default.

Can it run automatically?

Yes. Mback.py is a normal local script, so Windows Task Scheduler or another scheduler can run it on a chosen schedule. The dashboard does not need to remain open for scheduled backups.

Can I use the dashboard without Task Scheduler?

Yes. The Run Backup Now button triggers a single manual backup when the local dashboard is running. Automatic scheduling is optional.

Is the public demo connected to a real mailbox?

No. With demo mode enabled, every page uses only the fictional dataset in static/demo_data.json. Running a real backup and opening real backup files are both disabled.

What should never be uploaded to GitHub?

Never upload config.json, backup_state.db, backups/, .eml files, or email_backup.log. These should remain listed in .gitignore. See Security & Privacy.

How should I test restoration?

Periodically open a saved .eml file using a compatible mail client and confirm that its content, headers, and attachments are usable. A backup is only valuable if you can restore or inspect it when needed.
